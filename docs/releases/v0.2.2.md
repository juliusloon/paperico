# Paperico v0.2.2

日期：2026-10-01 · App build 4 · macOS 26+。

## 修复

- 窄窗口首页保留装饰图片，位于标题与按钮下方居中显示；桌面仍为左右布局。
- 修复原生 MinerU 云端签名上传错误：上传 PDF 时不额外设置 Content-Type，
  也不将 API Token 带到对象存储。原版本申请地址成功后会出现 HTTP 403。
  官方[批量上传说明](https://mineru.net/doc/docs/index_en/)要求上传时无需设置该请求头。
- 新增独立回归测试，模拟 API 申请与签名上传两个域名，检查请求头与批任务返回值。

- MinerU 完成后以一次流式模型请求处理完整文本、图表 caption、表格与公式；
  同时产生中文译文、逐块要点与逻辑角色、全文总结和去重方法索引。
- 去掉分批 Map、独立 Reduce、拆分补译与自动 JSON 修复生成请求。
- 以单个 JSON 对象流式返回，并增量解析节点，严格校验原编号、顺序与完整性；
  输出达到 token 上限时显示截断错误，原始响应保存为 `analyses/<paper-id>/single_pass.json`。
- 参考文献的作者、英文题名和出版信息在本地保留并生成导航节点，减少无须重复
  生成的内容；其他正文翻译与分析仍是一次请求。
- 对已返回节点的引号/反斜线错误提供本地格式修复，不调用模型；任务菜单也可
  恢复已保存结果，仍严格拒绝缺失节点与原文指纹不匹配。
- 输出预算按全文长度估算，通过 GET /models 探测显式输出容量；
  Kimi 全文翻译关闭思考输出，其他可调模型使用低思考预算，并不发送温度参数，避免 Kimi 限制温度值导致 HTTP 400。
  对话和笔记仍使用用户配置。预算是容量上限，实际费用依模型返回用量与服务计费。
- 修复 JSON 兜底正则读取不存在捕获组导致的崩溃；流式解析支持跨行 JSON，
  并每隔数秒保存返回正文，保留中断诊断证据。
- 启动时的处理任务等待已保存凭据读取完毕，避免误报未配置模型。
- 重新翻译后重新监听任务状态，处理期间隐藏上一次的失败提示；同一分析阶段
  只轮询轻量状态，结果落盘后再刷新全文。
- 笔记使用 Markdown 文档类型，默认导出 `.md`；生成后直接显示下载按钮，
  生成或导出失败会显示错误并保留已选回答。导出改由小型原生保存面板桥接处理，
  用户选择目标位置后以 UTF-8 原子写入，避免原 SwiftUI 导出面板无法确认保存。
- 附带原文段落时发送完整原文（单段上限 6000 字符、整体上限 18000 字符），
  避免只发送 240 字符预览而遗漏问答证据。
