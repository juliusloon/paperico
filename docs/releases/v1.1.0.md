# Paperico v1.1.0

发布日期：2026-10-07。App build 11。基线：1.0.1（App build 10）。需要 Apple Silicon Mac 和 macOS 26 或更高版本。

1.1.0 是一个**收敛版本**：把 1.0.x 留下的多处同一不变量实现收拢到各一处，并补齐唯一
明显缺失的能力（论文元数据识别）。不新增阅读器形态，不改渲染管线，不动凭据体系。

## 新增

- **论文元数据自动识别**：解析完成后从原文出版信息中识别 DOI / arXiv ID，命中 DOI 时
  查询 Crossref、命中 arXiv 时查询其 Atom 接口，自动补全**作者、年份、期刊**。此前这些
  字段建库时为空且全仓无写入点，论文卡片与 MetaCard 的对应渲染分支一直是空的。
  - 识别失败**静默降级**，绝不阻塞解析与翻译；查询各有 8 秒硬超时。
  - 没有 DOI / arXiv 的论文行为完全不变：不新增等待、不新增错误态。
  - 你手改过任意元数据字段后（`meta_source` 记为 `manual`），自动识别不再覆盖你的值。
- **按 DOI / arXiv 去重**：解析完成后从原文识别 DOI / arXiv，在进入模型分析前完成同
  标识符去重——同一篇论文的预印本与正式版字节不同、SHA-256 不同，此前会被当作两篇
  论文入库，现在会被识别为重复并指向已有论文。
- **MCP `brief` 资源**：外部 Agent 可先读一份压缩上下文（逻辑链 6000 字符预算、方法索引
  Top-40，`§` 章节标题恒留），需要原文时再读 `blocks`。此前 MCP 端直接返回全量 Block，
  只有 6 MiB 上限兜底。它与 App 内对话**共用同一套**压缩实现（不是另写一份）。
- **未引用文件报告**：库管理页新增「未引用文件」，列出磁盘上存在但索引里没有对应记录的
  文件（永久删除中途失败、旧版残留、手工拷入），显示路径、体积与类型。
  **默认只报告不删除**；删除需勾选并二次确认，逐项执行、失败可重试。

## 变更

- **本地 MinerU 解析改为串行**（同一时刻只解析一篇）。本地服务就是这台机器上的同一个
  实例，并发提交两份只会互相拖慢；云端解析与模型调用保持 2 并发不变。
  批量导入本地论文时总耗时会变长，这是有意的取舍。
- **论文库索引 schema 升到 v2**（新增 `doi` / `arxiv_id` / `meta_source`）。升级是**单向
  的**：1.1.0 写过的库 1.0.x 打不开，会收到明确的「请升级」提示。
  - 原因：1.0.x 虽能读懂新字段，但写回时会静默丢弃它们——降级会悄悄丢数据。显式拒绝比
    静默损坏好。
  - 首次打开旧库时会在迁移前生成 `library.json.bak-v1-<时间戳>` 备份并保留；
    迁移失败则保留原文件，不会进入半迁移状态。
  - 迁移逻辑只有一个入口（`LibraryIndexMigrations`），新增字段只允许在那里落。

## 开发者可见

- 新增真实论文 opt-in 解析回归（`PAPERICO_E2E_PDF_DIR`）和已分析库副本检查
  （`PAPERICO_E2E_LIBRARY_DIR`），env 缺失时 skip，已配置服务的实际失败会让测试失败。
  `macos/scripts/verify_real_pipeline.sh` 另行验证真实 App 上传与全管线、三篇排队及元数据落盘；
  需要显式配置 MinerU 和 LLM，使用隔离库，凭据只在内存中保留。真实 PDF 与解析产物不入仓库。
- 新增磁盘契约 fixture 与 MCP 契约快照（`UPDATE_SNAPSHOT=1` 刷新）。刷新快照必须在提交
  信息里说明契约为何变化，见 `CONTRIBUTING.md`。
- 已下线的 FastAPI 后端契约脚本标注为历史参考：它守护的是不再发布的服务，只在本地存在
  `backend/` 时可运行，原生 CI 从不调用它。

## 安装与升级

- 数据目录 `Application Support/Paperico/` 结构不变：论文库、PDF、笔记、对话、方法分组
  全部保留。
- 无需任何手工操作。首次打开 1.0.x 的论文库时会自动迁移，并在同目录留下一份
  `library.json.bak-v1-<时间戳>`。
- 从 1.1.0 降级回 1.0.x 会被明确拒绝（这是刻意的，见上）。
- 新解析的论文会识别元数据；已完成旧论文的元数据不会在启动时自动回填。
- 若旧版保存的附录没有译文，可以在阅读器选择「重新翻译」生成完整结果。

## 发布前修复

- 保留首页含 DOI / arXiv 的页眉、页脚出版信息，避免解析器将标识符提前丢弃。
- arXiv 改用 HTTPS；元数据查询拒绝非成功 HTTP 状态，并以总时长限制持续流式响应。
- 保留合法 DOI 内的括号，正确编码 URL 保留字符。
- 同一次库操作内登记标识符与判断重复，防止并发论文互相判重；重复记录不会阻塞已有论文重试。
- 修复符号链接路径（包括 macOS 的 `/var` → `/private/var`）导致下载解包后清单路径失效。
- 修复真实回归的空库永久跳过、解析失败被误记为 skip，以及图表/公式译文检查使用错误字段。
- 中英文 README 下载版本与发布说明链接同步为 1.1.0。
- 论文卡片年份按年份显示，修复新元数据使 `2026` 被显示为 `2,026` 的格式问题。

## 验证

- `swift test --package-path macos`：212 个测试，0 失败，3 个 opt-in 默认跳过（202 个核心、
  10 个 MCP；含索引迁移、元数据五路径、并发判重与重试、总时长超时、编排顺序、
  `brief` 预算、孤儿报告与误删防线、降级拒绝、时间戳定宽、契约快照）。已验证故意重命名一个
  MCP 工具会让快照测试变红。
- 完整 App target 编译通过（Debug / Release）；8 个脚本测试通过（1 个 opt-in 跳过）。
- **降级验证（端到端，用真实 1.0.1 源码）**：

  ```sh
  macos/scripts/verify_downgrade.sh
  ```

  从 git 历史取出 1.0.1 的解码源码编译成独立程序，喂入 1.1.0 写出的 v2 库：
  ```
  CONTROL_OK: 1.0.x 接受 v1 库
  PASS: 1.0.x 明确拒绝 v2 库 -> STORAGE_FAILED / 论文库由更新版本创建，请升级 Paperico 后再打开。
  ```

  带对照组（v1 必须被接受），否则"拒绝 v2"没有说服力。**这条断言不验证会失真**——
  如果只对着手抄的解码规则测试，抄错就会得出相反结论。

### 真实环境验收

- 三篇真实论文通过生产 `PapersStore.upload → PaperPipeline` 导入，观察到本地解析峰值为 1、
  等待队列峰值为 2；三篇均完成并持久化 DOI、作者、年份和期刊。
  一次模型段落 ID 错误被拒绝保存，手动继续后复用前五段，仅生成剩余内容，不重新上传或解析。
- 两篇真实 PDF 解析、三篇完成库的 sidecar 指纹与译文检查、外部客户端检查均通过，三项 opt-in 0 跳过。
- Release App 使用隔离真实库确认论文卡片作者/年份与 MetaCard 期刊；原用户库在验收后恢复。
- 外部 Python 进程通过生产 MCP HTTP 服务读取真实库的 `brief` → `blocks`，成功追溯 299 个原文块。
- Release DMG 可挂载并启动 App；内部版本为 1.1.0 / 11，ad-hoc 签名与四项 Sandbox/MCP 权限保留，
  同时提供 SHA-256 校验文件。本包沿用现有分发方式，未做 Developer ID 签名或 Apple 公证。
