# Paperico v1.1.0

发布日期：待定。基线：1.0.1（App build 10）。需要 Apple Silicon Mac 和 macOS 26 或更高版本。

1.1.0 是一个**收敛版本**：把 1.0.x 留下的多处同一不变量实现收拢到各一处，并补齐唯一
明显缺失的能力（论文元数据识别）。不新增阅读器形态，不改渲染管线，不动凭据体系。

## 新增

- **论文元数据自动识别**：解析完成后从原文出版信息中识别 DOI / arXiv ID，命中 DOI 时
  查询 Crossref、命中 arXiv 时查询其 Atom 接口，自动补全**作者、年份、期刊**。此前这些
  字段建库时为空且全仓无写入点，论文卡片与 MetaCard 的对应渲染分支一直是空的。
  - 识别失败**静默降级**，绝不阻塞解析与翻译；查询各有 8 秒硬超时。
  - 没有 DOI / arXiv 的论文行为完全不变：不新增等待、不新增错误态。
  - 你手改过任意元数据字段后（`meta_source` 记为 `manual`），自动识别不再覆盖你的值。
- **按 DOI / arXiv 去重**：同一篇论文的预印本与正式版字节不同、SHA-256 不同，此前会
  被当作两篇论文入库；现在会被识别为重复并指向已有论文。
- **MCP `brief` 资源**：外部 Agent 可先读一份压缩上下文（逻辑链 6000 字符预算、方法索引
  Top-40，`§` 章节标题恒留），需要原文时再读 `blocks`。此前 MCP 端直接返回全量 Block，
  只有 6 MiB 上限兜底。它与 App 内对话**共用同一套**压缩实现（不是另写一份）。
- **未引用文件报告**：库管理页新增「未引用文件」，列出磁盘上存在但索引里没有对应记录的
  文件（永久删除中途失败、旧版残留、手工拷入），显示路径、体积与类型。
  **默认只报告不删除**；删除需勾选并二次确认，逐项执行、失败可重试。

## 变更

- **本地 MinerU 解析改为串行**（同一时刻只解析一篇）。本地服务就是这台机器上的同一个
  实例，并发提交两份只会互相拖慢；云端解析与模型调用保持 2 并发不变。
  批量导入本地论文时总耗时会变长，这是有意的取舍。
- **论文库索引 schema 升到 v2**（新增 `doi` / `arxiv_id` / `meta_source`）。升级是**单向
  的**：1.1.0 写过的库 1.0.x 打不开，会收到明确的「请升级」提示。
  - 原因：1.0.x 虽能读懂新字段，但写回时会静默丢弃它们——降级会悄悄丢数据。显式拒绝比
    静默损坏好。
  - 首次打开旧库时会在迁移前生成 `library.json.bak-v1-<时间戳>` 备份并保留；
    迁移失败则保留原文件，不会进入半迁移状态。
  - 迁移逻辑只有一个入口（`LibraryIndexMigrations`），新增字段只允许在那里落。

## 开发者可见

- 新增真实论文 opt-in 全管线回归（`PAPERICO_E2E_PDF_DIR`），env 缺失时 skip 而非 fail，
  不进默认路径；真实 PDF 与解析产物不入库。
- 新增磁盘契约 fixture 与 MCP 契约快照（`UPDATE_SNAPSHOT=1` 刷新）。刷新快照必须在提交
  信息里说明契约为何变化，见 `CONTRIBUTING.md`。
- 已下线的 FastAPI 后端契约脚本标注为历史参考：它守护的是不再发布的服务，只在本地存在
  `backend/` 时可运行，原生 CI 从不调用它。

## 安装与升级

- 数据目录 `Application Support/Paperico/` 结构不变：论文库、PDF、笔记、对话、方法分组
  全部保留。
- 无需任何手工操作。首次打开 1.0.x 的论文库时会自动迁移，并在同目录留下一份
  `library.json.bak-v1-<时间戳>`。
- 从 1.1.0 降级回 1.0.x 会被明确拒绝（这是刻意的，见上）。

## 验证

- `swift test --package-path macos`：172 个测试全绿（含新增的索引迁移、元数据五路径、
  `brief` 预算、孤儿报告、时间戳定宽与两份契约快照）。已验证故意重命名一个 MCP 工具会让
  快照测试变红。
- 真实论文回归（需本地 MinerU）：

  ```sh
  PAPERICO_E2E_PDF_DIR=/path/to/pdfs swift test --package-path macos
  ```

- 降级验证：1.1.0 写过的库用 1.0.1 打开应收到明确「请升级」提示，而不是静默丢字段。
- 本地 MinerU 模式：连续导入 3 篇，确认串行解析且不卡死。
- MCP 手测：外部客户端读 `brief` → 读 `blocks` 两步链路可用；既有 10 个工具行为不变。
